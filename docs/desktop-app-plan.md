# 车车 CRM 桌面版（Mac 先行）规划

> 状态：**M0、M1 已完成**（2026-11-16），下一步 M2 常驻监听。

## 0. 目标与已定的原则

用户在自己的 Mac 上装一个软件，打开后：

1. 主窗口就是 CRM 网页，登录一次即可，不用再手动复制运行器令牌。
2. 软件把指纹浏览器（Camoufox）和现有的环境运行器内置在里面。社媒账号在本机后台一直挂着，**私信几秒内进 CRM 收件箱**。
3. 用户也能像用 AdsPower 一样，点「打开环境」，在本机弹出这个账号的浏览器窗口，手动操作（登录、扫码、输 X 私信密码等）。

已确定的原则：

| 事项 | 决定 |
|---|---|
| 默认执行位置 | **本地**。所有账号默认跑在负责人的桌面软件里 |
| 云端运行器 | **企业设置里手动打开才启用**（默认关）。关闭时 CRM 不再拉起 Vercel Sandbox，控制云端资源占用 |
| 先做的平台 | Mac（Apple Silicon 优先，Intel 同时出包）。Windows 放到后面 |
| 先做实时的平台 | TikTok（已适配新版私信页）。X、Instagram、Facebook、LinkedIn 依次跟上 |

## 1. 现状（能直接复用的部分）

- `scripts/matrix-runner.mts`：Node 常驻进程，凭企业令牌轮询 `/api/matrix/runner/poll` 领任务，每个账号一个 Camoufox 持久化环境（固定指纹、自己的代理、出口 IP 对齐时区/语言/WebRTC），已支持 login / open / check / inbox / reply。**本身就是按「装在用户电脑上」设计的**，只是现在要在项目目录里用命令行启动。
- `scripts/matrix-inbox.mts`：各平台读私信、发私信。
- CRM 已有：任务队列、运行器心跳（`MatrixRunner`）、收件箱写入接口、实时画面（云端用）。
- 云端运行器（`src/server/matrix-cloud.ts`）：只要配置了 Vercel 变量，就在 5 个地方自动拉起：
  `src/server/inbox.ts`、`src/server/matrix-schedule.ts`、`src/app/(app)/inbox/actions.ts`、`src/app/(app)/social/matrix/actions.ts`、`src/app/api/matrix/jobs/[id]/live/route.ts`。
- Camoufox 0.5.9（npm 包 MIT，浏览器 MPL-2.0），Mac 上内核加地理库约 **320 MB**。

**现在缺的**：普通用户能装的外壳；账号和设备的绑定（现在企业里任何运行器都能领任何账号的任务）；常驻监听；云端开关。

## 2. 总体架构

```
┌──────────── 车车 CRM.app（Electron）────────────┐
│ 主进程                                           │
│  ├ 主窗口：加载 https://crm.caraicrm.com          │
│  ├ 菜单栏图标：在线状态、挂着几个账号、退出        │
│  ├ 设备配对：用当前登录用户换一个设备令牌          │
│  └ 管理子进程（崩溃自动重启、版本更新）            │
│                                                  │
│ 运行器子进程（复用 matrix-runner，Electron 自带 Node）│
│  ├ 任务模式：领 login / open / check / reply 任务  │
│  └ 常驻模式：给本机负责的账号各开一个后台环境，     │
│     停在私信页，几秒检查一次，有新消息立刻推给 CRM  │
│                                                  │
│ Camoufox 内核（首次启动下载到 ~/Library/Application Support） │
└──────────────────────────────────────────────────┘
            │ HTTPS（设备令牌）
┌───────────▼──────── CRM 服务器 ──────────────────┐
│ 设备表 · 账号归属设备 · 任务按设备分发 · 收件箱     │
│ 企业设置：云端运行器开关（默认关）                   │
└──────────────────────────────────────────────────┘
```

**为什么选 Electron**：运行器和 Camoufox 启动器都是 Node 写的，Electron 自带 Node，可以原样复用，不用重写。Tauri 包更小，但还得另外带一个 Node，反而更复杂。

**运行器跑在子进程里**（`utilityProcess` 或 `ELECTRON_RUN_AS_NODE`），不放进主进程：运行器或浏览器崩了不会拖垮界面，主进程负责重启它。

## 3. 关键设计

### 3.1 登录与设备配对（不再手动复制令牌）

1. 用户打开软件，主窗口里正常登录 CRM。
2. 网页检测到运行在桌面版里（主进程通过 preload 暴露 `window.chechedesktop`），调用新接口 `POST /api/desktop/pair`，用当前登录会话换一个**设备令牌**（绑定 用户 + 企业 + 设备 ID）。
3. 设备令牌存进 macOS 钥匙串，运行器用它领任务。用户退出登录或在 CRM 里「移除设备」，令牌立即失效。

新增表 `MatrixDevice`：id、企业、用户、设备名（如「Louis 的 MacBook Pro」）、系统版本、软件版本、令牌哈希、最近在线时间。现有的 `MatrixRunner` 心跳表保留，云端运行器继续用。

### 3.2 账号归属设备

- `MatrixAccount` 加 `deviceId`：这个账号的浏览器环境放在哪台设备上。
- 在桌面版里新建或登录一个账号时，自动归到当前设备。已有的账号在 CRM 里可以「移到这台电脑」（见 3.6 迁移）。
- 领任务：设备只领**归属自己的账号**的任务。没有归属设备、又开了云端的账号，才交给云端。
- 一个账号同一时间只在一个地方运行，避免本机和云端同时登录被平台当成异常。

### 3.3 常驻监听（实时收私信）

运行器启动后，向 CRM 拉取「本机负责且开了收私信」的账号列表，每个账号：

1. 用无界面模式启动该账号的环境，停在私信页，**不再每 10 分钟重新打开浏览器**。
2. 每 5～10 秒（带随机）在页面里读一次会话列表预览，和上次比对。有变化才点开对应会话读消息，通过现有的收件箱接口推给 CRM。TikTok 的读取逻辑直接复用这次写的 `tiktokSync` / `tiktokRead`。
3. 当前打开的会话用 `MutationObserver` 盯着，对方发来新消息时立刻上报。
4. 每 30～60 分钟随机刷新一次页面，防止页面长时间挂着状态失效。检测到掉线就停止这个账号，并按现有流程提醒重新登录。
5. 回复：CRM 里点发送，任务直接交给这个常驻页面执行，不再另开浏览器，**回复也是几秒发出**。

CRM 收件箱页面改为每几秒刷新一次（或用 SSE 推送），新消息不用手动刷新。

本机在线时，服务器不再给这些账号排 10 分钟一次的定时同步，避免重复打开。

### 3.4 打开环境（手动操作）

点「打开环境」时，常驻的无界面环境先关掉，再用同一个环境目录弹出**可见窗口**（同一个环境目录不能同时被两个浏览器打开）。用户关掉窗口后，自动恢复后台常驻。登录任务也一样，直接在本机弹窗口，不再走云端的实时画面。

### 3.5 云端运行器开关（默认关）

- `Tenant` 加 `matrixCloudEnabled`（默认 `false`），在「设置 → 社媒矩阵」里开关，仅管理员可改。
- 把上面 5 处 `cloudConfigured()` 判断统一换成一个 `cloudEnabledFor(tenantId)`：服务器配了 Vercel 变量，**并且**企业打开了开关，才拉起云端。
- 关闭时，账号所在设备不在线，任务就排着不执行，界面显示「设备离线：Louis 的 MacBook Pro」，定时同步也跳过，不会一直堆积。
- **这一项不依赖桌面版，可以第一个做、马上上线**。现在已经在云端跑的两个账号（TK、X - Louis）需要先迁到本机，或者给你的企业先打开开关，否则关掉后它们就停了。

### 3.6 环境迁移（云端 ↔ 本机、换电脑）

环境目录（Cookie、本地存储、X 私信的解锁状态、指纹）打包压缩，用企业密钥加密后传到 OSS，另一边下载解开。迁移期间账号锁定，两边都不运行。用途：把现在云端的账号搬到本机；换电脑；员工离职交接。

第一版先做「云端 → 本机」和「本机 → 本机」，满足把现有账号迁下来、换电脑这两种情况。

### 3.7 软件本身

- **安装包**：DMG，arm64 和 x64 各一个。Camoufox 内核不打进安装包，首次启动从我们的 OSS 镜像下载（国内从 GitHub 下载太慢），带进度条和校验。安装包控制在 150 MB 以内。
- **签名和公证**：需要 Apple 开发者账号（每年 99 美元），否则用户双击会被系统拦截。下载的 Camoufox 内核由软件自己下载、不带隔离标记，可以直接运行。
- **自动更新**：`electron-updater`，更新源放 OSS。平台改版时推一个新版本，用户重启软件就生效。运行器代码也跟着软件版本走。
- **常驻**：关掉主窗口只是隐藏，软件留在菜单栏继续挂着。可选「开机自动启动」。Mac 合盖睡眠时会断开，醒来自动恢复，并补一次完整同步。
- **资源**：每个常驻环境约 300～500 MB 内存。默认最多同时挂 5 个账号（可调），超出的退回定时同步。菜单栏里显示当前占用。

## 4. 分期

| 阶段 | 内容 | 预计 |
|---|---|---|
| **M0** | 云端开关（默认关），5 处云端入口统一判断；设备离线的提示 | 0.5 天，可以先上线 |
| **M1** | Electron 外壳（主窗口、菜单栏、preload）；设备配对和设备令牌；运行器作为子进程内置；Camoufox 首次下载；账号归属设备、按设备分发任务；本机弹窗登录和打开环境 | 4～5 天 |
| **M2** | 常驻监听（TikTok 先做）；回复走常驻页面；收件箱自动刷新；在线时跳过定时同步 | 3～4 天 |
| **M3** | 环境迁移（云端 → 本机、换电脑）；签名公证、DMG、自动更新；你自己的账号试跑几天 | 3 天 |
| 之后 | X 新版加密聊天、Instagram、Facebook、LinkedIn 的常驻监听；Windows 版 | |

M1 完成后，你就能在自己的 Mac 上装起来，用本机代替云端跑现有功能。M2 完成后实现实时收私信。

### 进度（2026-11-16）

- **M0、M1**：已上线（PR #71）。
- **M2**：已完成。
  - 桌面版运行器每 30 秒调 `/api/matrix/runner/watch` 报心跳、取回该常驻的账号：归属本机、已登录、开了收私信、TikTok、未在迁移。
  - 每个账号一个无界面浏览器停在私信页，5～10 秒看一眼会话列表。预览去掉了相对时间，只打开有变化的会话；每 5 分钟顺带看一次「消息请求」；30～60 分钟刷新一次页面，顺便确认登录。最多 5 个账号（`MATRIX_MAX_WATCH`）。
  - 新消息报到 `/watch/<账号>`。登录失效会标记账号、通知负责人；连续出错 5 次就停 10 分钟。
  - 收私信、发私信、检查登录直接在常驻页面上做。登录、打开环境、迁移前先停掉常驻，做完自动恢复。
  - 90 秒内有心跳的账号，服务器不再排定时同步和定时检查。账号列表显示「实时收私信中」，收件箱 4～6 秒轮询一次。
  - 菜单栏图标旁显示常驻账号数，菜单里列出账号名。
- **M3**：已完成。
  - 环境迁移流程：
    1. 已登录的账号点「迁到这台电脑」或「取消归属电脑」（目标是云端）时，在原位置排「迁出」任务。
    2. 运行器把环境目录打包（不含缓存和锁文件），用服务器下发的一次性密钥 AES-256-GCM 加密，按 16 MB 分块传到 OSS（`matrix-env/<企业>/<任务>/n.bin`）。
    3. 迁出完成后，账号归属换到新位置，并排「迁入」。新位置下载、校验、解密、解开，再打开浏览器确认登录。迁入结束后删除密钥和密文。
  - 迁移期间不排其它任务，也不常驻。原位置离线、账号没登录或云端没开时，退回原来的「换位置后重新登录」。
  - 云端关着也能迁出：云端运行器只领迁出任务。
  - 安装包：
    - electron-builder 出 DMG 和 ZIP（arm64、x64），带图标和菜单栏模板图标（`desktop/scripts/make-icons.mjs` 生成），开启 hardened runtime 和 entitlements。
    - 有签名证书和 Apple 账号环境变量时，自动签名、公证。
  - 自动更新：
    - electron-updater 走 `https://crm.caraicrm.com/api/desktop/update`（OSS `desktop/` 目录，yml 直接返回，安装包 302 到签名链接）。
    - 用 `pnpm desktop:publish` 发布；设置页有下载链接 `/api/desktop/download?arch=arm64|x64`。
  - 迁入结束后会尝试删除密文，但现在的 OSS AccessKey 没有 DeleteObject 权限（403）。建议在 OSS 上给 `matrix-env/` 前缀配「1 天后删除」的生命周期规则。密钥用完就删了，留下的密文也解不开。
  - **还差**：Apple 开发者账号（签名、公证；没签名的 Mac 版不能自动更新）；真实账号试跑。

## 5. 需要你准备或决定的

1. **Apple 开发者账号**（个人或公司，每年 99 美元）。没有它也能先开发和自用，但发给其他用户前必须签名公证。用公司名注册，安装时显示的是公司名。
2. 软件名称和图标（暂定「车车 CRM」，图标沿用网站的）。
3. 安装包和更新文件的下载地址（建议用现有 OSS 新建一个目录，配 CDN 域名，例如 `download.caraicrm.com`）。

## 6. 风险

- **长时间挂着的风控**：一直停在私信页比定时重开更像真人，但仍属于自动化。M3 试跑时重点观察有没有掉线、验证码、限制。
- **平台改版**：读私信还是靠识别页面。出错时截图上报（这次排查 TikTok 用的就是这个办法，做成常驻功能），配合自动更新尽快修复。
- **电脑关机就收不到**：这是本地优先的代价。需要 7×24 小时的企业，可以在设置里打开云端兜底。
- **Camoufox 仍标记为开发中**：版本由软件固定，升级前先在试点账号上验证。
